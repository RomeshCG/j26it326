## 1. Overview & Objectives

Component 3 (M3) manages the operational core of the microfinance platform:
1. **Loan Lifecycle Operations:** Origination, application evaluation, disbursement confirmation, repayment schedules, and portfolio tracking.
2. **Field Collections & Recovery:** Officer daily collection routing, overdue queues, group lending meetings, and offline receipt logging.
3. **ML Early Warning System (EWS):** Proactive detection of loan distress ahead of traditional reactive PAR30 delinquency triggers, complete with explainability signals for loan officers.

## 3. Backend (BE) Implementations

All M3 backend services run on Express + TypeScript under the `/api/m3` route namespace.

### Route Modules (`backend/src/routes/m3/`)

- **`/api/m3/loans`** (`loans.ts`): Loan retrieval, loan status lifecycle transitions (Approved → Disbursed → Active → Closed), and repayment schedule generation.
- **`/api/m3/applications`** (`applications.ts`): Loan application submission, intake review, and scoring integration.
- **`/api/m3/collections`** (`collections.ts`): Payment receipt processing, transaction logging, and schedule balance decrement.
- **`/api/m3/ews`** (`ews.ts`): EWS alert retrieval, alert resolution / disposition tracking, and batch scoring triggers.
- **`/api/m3/par`** (`par.ts`): Portfolio-at-Risk calculation (PAR1, PAR30, PAR60, PAR90) aggregated across branches and loan products.
- **`/api/m3/borrowers`** (`borrowers.ts`): Borrower profiles, KYC data, and associated active loan records.
- **`/api/m3/products`** (`products.ts`): Microfinance loan product definitions (interest rates, tenures, repayment frequencies).
- **`/api/m3/groups`** (`groups.ts`): Group lending and village banking center management.

### Authentication & Tenant Security (`backend/src/lib/m3/auth.ts`)
- **M4 Real Login Alignment:** Replaced static mock authentication with M4's central `authenticate`, `resolveTenantContext`, and `requireRole` middleware.
- **RBAC Protected:** Routes enforce roles (`LOAN_OFFICER`, `BRANCH_MANAGER`, `ADMIN`) using real JWT claims.
- **Multi-Tenant Isolation:** All database queries operate via `req.tenantPrisma` to prevent cross-tenant data leakage.

## 4. Machine Learning (ML) Implementations

The EWS ML pipeline predicts borrower distress ahead of conventional reactive PAR30 metrics.

### Pipeline Components (`ml/m3_ews/`)

1. **Feature Engineering & PAR Mapper:**
   - `features/par_to_ews_matrix.py`: Transforms loan repayment histories, arrears velocity, and transaction cadence into a normalized feature matrix.
   - Key features include: `days_since_last_payment`, `repayment_on_time_rate_3m`, `avg_days_late_3m`, `consecutive_missed`, and `loan_to_income_ratio`.
2. **Model Families Benchmarked (`train/`):**
   - **Candidate 1 (Primary Production):** Gradient Boosted Trees (`XGBoost`) — selected for near-instant inference speed and exact TreeSHAP feature explanations.
   - **Candidate 2 (Sequence Benchmark):** Bi-layer Recurrent Neural Network (`PyTorch LSTM`) — models multi-period repayment trajectories across consecutive installments.
3. **Batch Scoring Engine:**
   - `serve/batch_score.py`: Nightly batch runner that loads active loans, applies the trained model, calculates risk percentiles, and generates distress alerts directly into the database.
4. **Evaluation & Shadow Pilot:**
   - `evaluate/evaluate_model.py`: Generates confusion matrices, ROC-AUC, and Precision-Recall metrics with strict temporal cohort splits (preventing lookahead bias).
   - `evaluate/shadow_pilot.py`: Evaluates lead time advantages vs. standard rule-based PAR30 alerts.

## 5. Cross-Module Integration Points (Action Items for Team)

### For M1 (Credit Risk & Underwriting)
- **Application Scoring:** C3's application flow is prepared to request initial credit risk scores (`POST /api/m1/risk/assess` or equivalent).
- **Dataset Alignment:** C3 is training on the shared clean PAR dataset (`par30_clean_no_pii.csv`). Let's ensure column mappings for arrears and customer IDs stay consistent.

### For M2 (Ledger & Mission Intel)
- **Disbursement Events:** When C3 disburses a loan, we emit a `LOAN_DISBURSED` event with `{ loanId, borrowerId, principal, disbursementDate, branchId }`.
- **Collection Events:** When a repayment is recorded, C3 emits a `PAYMENT_COLLECTED` event with `{ loanId, amount, principalPortion, interestPortion, paymentDate }`.
- *Note:* C3 never writes directly to M2 ledger tables; we send events only.

### For M4 (Graduated Trust, Governance & Auth)
- **Auth Tokens:** C3 routes now strictly validate M4's Bearer JWT tokens.
- **Tenant Context:** C3 uses M4's `resolveTenantContext` to attach the appropriate tenant database client.
